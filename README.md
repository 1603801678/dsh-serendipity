# dsh-serendipity（缪斯）

给 DeepSeek Harness 的 **创造力插件**：内置一个跨领域「结构素材库」，让 agent 在工作中按需抽取随机素材、
阅读、强行把素材的结构映射到自己当前的问题上，并记录哪些类比真的产生了突破。

> 创新的核心不是凭空发明，而是跨领域知识的**结构性迁移**（波尔←太阳系、李斯特←农业消毒）。
> 这个插件把这一步做成机械动作：素材是随机的、低概率有用的、并且**要求被映射**。

```
serendipity_draw  →  读素材  →  强行映射到当前问题  →  serendipity_note（含 miss）
      ↑                                                          │
      └──────────── serendipity_learn（把新发现的结构沉淀回库） ←──┘
```

## 为什么是这样设计的

| AI 的已知局限 | 插件对应的机制 |
| --- | --- |
| 远距离类比的「关系对齐」不稳定 | 每条素材带 `structure`（可迁移的形状）、`structureTags`（跨域检索骨架）和 `bridge`（提问式的映射提示）——把对齐这一步变成必须回答的问题 |
| 系统性偏向组合式创造，缺转化式创造 | `serendipity_note` 的 `transformation` 字段专门标记「是否改变了问题定义本身」，并统计比率 |
| 缺「意外性」机制 | 随机抽取 + 项目内去重 + 强制跨域交错（相邻素材绝不来自同一领域）；允许 0 命中，不要求产出 |
| 容易强化既有框架 | `violate: true` 让抽取偏向「打破假设 / 替换判据 / 重定义问题」的素材 |

## 安装

### 从 GitHub / 本地目录（开发中）

```powershell
# 把本仓库 link 进某个 dsh profile（这里用 web profile）
$env:DSH_HOME = "$env:USERPROFILE\.dsh"
node <dsh安装目录>\node_modules\@deepseek-ai\dsh\lib\bin.js plugin --profile web add "link:E:/path/to/dsh-serendipity"
# 然后重启 dsh web（宿主插件不走 HMR，必须重载进程才生效）
```

### 从 npm（发布后）

```powershell
dsh plugin --profile web add @1603801678/dsh-serendipity
```

### 让插件能解析 dsh SDK（用 `link:` 安装时必需）

`link:` 安装会直接指向源码目录，Node 从**源码目录**向上解析 `@deepseek-ai/dsh-tools` 等 peer 依赖，
而那里通常没有 `node_modules`。两种做法：

1. **推荐**：在本仓库下建一个 `node_modules/@deepseek-ai` junction 指向 dsh 安装的 SDK 目录：

   ```powershell
   $sdk = "<dsh安装目录>\node_modules\@deepseek-ai\dsh\node_modules\@deepseek-ai"
   $mine = "<本仓库>\node_modules\@deepseek-ai"
   New-Item -ItemType Directory -Force -Path $mine | Out-Null
   cmd /c mklink /J "$mine\dsh-tools" "$sdk\dsh-tools"   # 其余同法
   ```

   需要：`dsh-tools`、`dsh-llm`、`dsh-session`、`dsh-scope`、`dsh-agent`、`cordis`、`schemastery`、`cosmokit`、`dsh-system-prompt`。

2. 用 `pnpm add` 正式安装到 profile（由 pnpm 建立依赖链接）。

**插件在 peer 依赖缺失时的行为**：宿主进程会拒绝加载该插件行，profile 里其它插件仍照常工作——
这意味着 web GUI 不会因为本插件坏掉而无法启动。

## 工具

| 工具 | 用途 |
| --- | --- |
| `serendipity_draw` | 抽取随机素材。参数：`purpose`（你在做什么）、`bias`（倾向：类别/标签/领域）、`avoid`（回避）、`violate`（要「打破假设」类）、`allowRepeat`、`collide`（按「组」发：同结构、异来源的成对素材）、`scope`（`far` 默认 / `near` 同领域基准 / `generate` 随机配对生成） |
| `serendipity_note` | 记录每条素材的结果。**被计入的是 `landed`**（说明结构去了哪里：写进了哪个文件/哪一节、或改写了哪个决定）；`hit`（自评有用）与 `transformation`（是否改变了问题本身，需配 `changedFrom`/`changedTo`）会被如实记录，但**不计入任何统计**；可选 `materialModel` 写自己对素材库的评估 |
| `serendipity_learn` | 把工作中学到的新结构沉淀成素材（写入用户目录，不污染插件包）。`kind` 三档：`add`（沉淀一条素材）/ `saveAnalysis`（保存同领域比较分析）/ `readAnalysis`（取回） |
| `serendipity_stats` | 库规模、本项目已读/剩余、**有落点的条数与自评有用条数（分开报）**、`bias` 可用词表、**覆盖度权重**、健康检查 |
| `serendipity_decompose` | 把作品拆成部件并逐一追问：每个部件是「假设」还是「必然」？去掉它会怎样？替代它的 2~3 种做法是什么？ |
| `serendipity_fetch` | **联网**抓取网页/API 正文（可达站点与查询语法见下），用于把最新资料提炼成素材 |

> 「同领域比较分析」的存取走 `serendipity_learn` 的 `saveAnalysis` / `readAnalysis`，不再是一个单独的工具
> ——「存一条发现」和「存一份分析」在调用方是同一件事，分开只会多一个没人用的工具。

### 什么时候该抽：开放式目标先抽再动手

提示词段落原先只写了**条件式**时机（「正在设计或做方案取舍时」「卡住了」「想质疑某个前提时」），
于是模型在「刚好有空」时才抽，而不是在「该抽」时抽。真实会话里的原始记录：它在**等四个子代理的间隙**
才想起插件，而且先自问了一句——「Hmm — is this appropriate? … the user hasn't mentioned it」。
换一次执行顺序（子代理提前返回），那一轮很可能一次都不抽，而插件对此**没有任何意见**。

现在「什么时候抽」写成两段：

1. **用户给的是「开放式目标」时，先抽一次再动手**——没指明方法的问题（「看看这个项目哪里能改进」
   「帮我设计一个 X」「换个思路」）；
2. 其余是原有的条件式时机。

这是纯提示词改动（约 +106 token），没有加任何机械注入：插件**仍然不会自己抽**，
`autonomous` 这一档的语义就是「工具可用 + 声明在提示词里，由 agent 自己判断」，只是把判断依据补全。

### 短期任务 vs 长期任务：插件自己判断，不问模型

插件按**真实证据**（已记录的结果条数、draw 轮次、项目持续时间）把项目分成 `session` / `campaign`，
而不是让模型填一个 `horizon` 参数——**免费的选择会退化成噪声**（模型在没有依据时会随便选一个）。

两种档位的**行为**不同，并且这个判断会打印在 draw 结果的第一行，所以猜错时是可见的、可自纠的：

| | 单次任务（session） | 长期任务（campaign） |
| --- | --- | --- |
| 提示词 | 一次给足，不啰嗦 | 鼓励沉淀、强调「改了问题定义就要写下改动前后」 |
| 记忆回灌 | 无 | **列出本项目此前写出落点的素材与你自己的映射笔记** |

回灌只引用 agent 自己写过的笔记（不代它编造）——长期任务会忘，这就是记忆；
它优先给有落点的条目（可查），但不隐瞒那些当时没看出用途的条目。

### `collide`：同一个形状，两个不相干的领域

普通抽取**刻意避免**一批里出现同一个结构形状（那样覆盖面才宽，`crowdingPenalty` 对共享形状罚
×0.55 / ×0.15）。但那个惩罚同时挡住了一种东西——**一个形状在两个远域里的两次出现**。
而真实会话里最有价值的成果恰恰是这么来的：用生态学的捕食者-猎物周期去修卡牌的派正反馈、
把「饱和曲线」和「延迟」摆在一起做取舍。那些配对是模型自己拼的，插件从来没给过。

`draw({ collide: true })` 就是反过来做：**按组**发素材，每组两条，共享同一个受控结构核心，
来源领域尽可能远（来源相同是**硬排除**——同一个领域里的两条只是重读，不是碰撞）。

输出不是「两条素材」，而是一个**三者的关系**：A 与 B 共享的那条结构在你手上对应什么？
A 成立而 B 不成立的地方，是不是说明了那条结构的**适用边界**？（边界往往比结构本身有用。）

三个实现上的取舍，都是量出来的而不是拍的：

- **配对是枚举后整体打分，不是「先选一个再选最远的」**。贪心顺序先优化相关性、再优化距离，
  实测给出过 `可靠性工程 / 航空航天` 配一条共享「可靠性」这个词的素材——「碰撞」距离只有 0.15。
  组通常只有几条，枚举全部组合很便宜，而且能同时优化两端。
- **选形状时按「这个形状最远能撞多远」加权**。有些形状只在相邻领域出现，撞不出东西；
  语料里能成对的形状中约六分之一的最佳距离低于 0.5。加上这一项后，实测平均距离从 **0.76 升到 0.84**、
  低距离配对从 **17.5% 降到 6.3%**（单对约 1.1 ms）。
- **`bias` 是过滤器，不是权重**。×12 的加权在 ~75 个竞争形状面前只有约 14% 的命中率，
  「`bias: "阈值"` 却给了别的形状」这种静默失败比不支持更糟。现在 `bias` 写结构标签会把候选
  **限制**在该形状上（走受控词表归一，所以写别名 `预警` 也能命中核心 `阈值`）；
  限制会让批次变窄时再退回覆盖率加权，退化而不是失败。

`collide` 仍然是**交付**（不是任务）：两条素材都会被标记为已读、计入抽取次数与去重预算。
需要「让插件指定方向、我去造素材」时用 `scope: "generate"`（那个才不记账）。

### `scope: "generate"`：不再等搜索引擎决定给你什么

内置语料只有 115 条，`serendipity_learn` 只能补上模型**恰好遇到**的东西——于是「随机素材」
的自由度其实被两件事锁住：库有多大，以及这一轮搜索恰好点开了什么。真实会话里最能说明问题的一幕是：
用户要求「抽点新的、随机的素材」，拿到什么完全取决于搜索引擎返回了什么。**随机的方向由别人决定。**

`scope: "generate"` 把随机权拿回来。它**不抽素材**，而是随机指定一对：

- **一个具体领域**——来自 `lib/fields.mjs` 的**领域地名志**（223 个，13 个家族：消防工程、电梯调度、
  冰川物质平衡、潜水减压、玻璃吹制退火、戏曲锣鼓点、训诂与校勘、破产重整、排队论……），
  每个家族带一句「这个领域的看点是」；
- **一个结构核心**——`lib/structure-tags.mjs` 的受控词表（76 个跨领域可迁移的形状）。

然后交给你一个生成任务：**去那个领域找一件真事，写出它的机理，提炼成素材再入库。**
素材的作者成本是零（模型自己写），来源面却是无界的（地名志可以一直加）。

三条刻意的设计：

1. **避让已读**：与本项目已读素材的 `origin` 词元重叠的领域会降权——「远」是唯一信号，
   再抽一个读过的方向等于浪费一次机会。
2. **记住抽过的对**：同一对（领域 × 核心）在最近 24 组内不重复。没有记忆时，模型会反复
   落在自己顺手的那几个领域上（这是实测行为，不是假想）。
3. **给替代项**：每对都附两个备选领域，让「这个组合说不通」成为**可以明说的答案**，
   而不是逼着写一条凑数的素材——`detail` 必须讲机理是 lint 的硬规则，凑数的会污染以后所有抽取。

它不计入抽取次数、不标记任何素材为已读、不占去重预算：**什么都没发出去，所以什么都不该记账。**

### `scope: "near"`：同领域素材当基准，不是当灵感

跨域素材提供「跳出」，同领域素材提供**基准**——你的作品是否新颖，只能在已存在的东西面前判定。
这是两种不同的活，所以 `near` 不抽语料，而是返回一份四步任务，其中第三步最值钱：

1. 找到 3~5 个**真实存在**的同领域作品（用 `web_search`，要具体到名称，不要泛指）；
2. 逐个抽出它们的**骨架**（核心动作、决策来源、张力机制、主动放弃了什么）；
3. **找共同假设**——它们全都默认成立、却没人质疑的那一条。那就是这个领域当前的天花板；
4. 列出它们合起来**没覆盖**的设计空间。

然后 **near 指出该动哪里，far 提供动它的结构**：把共同假设交给 `serendipity_decompose` 拆解，
再用 `serendipity_draw({ bias: 该部件的结构标签 })` 去远域找替代方案。

### `serendipity_fetch`：联网，但**抓取不等于入库**

插件自己联网抓正文。**可达清单是实测出来的**（2026-10-10 用 `tools/probe-sources.mjs` 探了 46 个目标，
32 个可达），并随工具说明一起交给模型——因为不写下来的代价实测过：一次真实会话的 13 次抓取里，
4 次撞 403、1 次把首页当成了文章、1 次把输出预算全花在 API 的 `*_url` 模板字段上。

| 类别 | 实测可达 |
| --- | --- |
| 中文设计/社区 | 机核**文章页** `/articles/<id>`、**B站专栏** `/read/cv<id>`、**集石桌游社区**（实践者讨论取舍）、3楼猫、游资网、雷科技、游研社、indienova |
| 中文科普/通用 | 少数派、果壳、中国科普博览、科学网博客、环球科学、阮一峰博客 |
| 海外科普/文化 | Quanta、Nautilus、Aeon、99% Invisible、The Marginalian、Phys.org、ScienceDaily、MIT News、Nature |
| 可搜索的 API | B站专栏搜索、少数派文章列表、Crossref、OpenAlex、arXiv、PubMed、Stack Exchange、GitHub 仓库搜索 |
| 随机入口 | 萌娘百科随机词条（wikipedia 不可达，这是唯一实测可用的随机源） |

不可达（写进说明，省得重试）：NGA、百度贴吧（含镜像，均 403）、`zhuanlan.zhihu.com`、
百度百科、Atlas Obscura、Smithsonian、archive.org，以及 wikipedia / HN / Reddit / DuckDuckGo。
注意 **`www.zhihu.com` 可达而 `zhuanlan.zhihu.com` 是 403**——所以这份清单是按 host 记的，不是按站点。

三个已经踩过并固化成机制的点：

- **`indexPage` 标记**：抓首页会拿到几百条导航短行、几乎没有正文。工具会把它标出来，
  并告诉你去抓具体文章页或搜索 API（提取本身不动，模型仍能看见里面确实没有东西）。
- **JSON 噪声剥除**：`*_url` / `node_id` 这类模板字段会被递归删掉，深层元数据折叠成 `{…}`。
- **拒绝二进制**：PDF 按 `content-type` 与 `%PDF` 魔数识别，直接说明「本工具只返回文本，
  改用 HTML 版页面或 API」，而不是把 973 KB 的压缩流当正文交出去。
- **查询语法**：arXiv 的空格关键词会被解析成 `OR`（实测返回 57 万条无关结果），短语要写 `all:%22短语%22`；
  Crossref/OpenAlex 加 `select=` 能把响应从 53 KB 压到 712 字节，加 `sort=published&order=desc` 才有「最新」。

抓回来的正文**不是素材**：必须先提炼成一条带 `structure` / `detail`（机理）/ `bridge` 的条目，
再用 `serendipity_learn` 入库；提炼不出可迁移结构就不要入库。这正好落地项目最初的判断——
**不是禁止外部内容，而是要求先被提炼成结构**。

### 外部素材也能记落点（否则最值钱的那批会丢）

`landed` 是唯一被计入的信号，而**从网络来的结构落点最多、也最新**。所以
`serendipity_note` 不再只认「插件自己发出的 id」：

- 给一个**自起的 id**（如 `ext-gstone-0prob`）或一个 **`label`**（结构名，会先按标题匹配语料）就能记；
- 匹配不到语料的记为**外部素材**：落点照样算数，但**不计入覆盖率**——「库读了多少」
  不能被库里本来就没有的东西抬高，否则覆盖度权重所依赖的那条中立线会被拉偏；
- 条目里也允许多条混合：**一条缺 id 不再让整批作废**（这是真实事故：
  8 条一次性全被 schema 拒绝，包括 agent 刚写进设计文档的那几条落点）。

统计里外部素材**单独报一行**（`externalNoted` / `externalLanded`），不混进「发出量→落点」的比率。

### `serendipity_decompose`：把「质疑约束」变成必须回答的问题

真实测试会话里 agent 已经在手工做这件事（自己追问「卡牌游戏是否一定需要洗牌」）。
这个工具把它固定成流程：给定待拆解的作品（可选给一份初版部件清单），返回一份**强制清单**——

- 每个部件必须回答 5 个问题，其中两个**无法靠描述现状交差**：
  「整块去掉会退化成什么」「替代它完成同一功能的 2~3 种做法（至少一种形态完全不同）」；
- 声明为「必然」的部件必须单独举证，举不出就改判为「假设」；
- 收尾检查强制找出**跨部件的共同假设**（那才是最该质疑的前提）、做**配对替换**、
  找出**删到极限后的最小可玩核心**、检查**信息通道**是否单一。

工具本身不给答案，它给的是**不能跳过的步骤**。每个「假设」再接
`serendipity_draw({ bias: 该部件的结构标签 })` 去取远域素材找替代方案，最后用 `serendipity_note` 记录。

**记录这一步不只是提示词要求，插件还会兜底提醒**：如果上次 `serendipity_draw` 的素材没被
`serendipity_note` 记录，下一次 draw 时插件会通过 deferred context 把那些素材的 id 直接
推给模型（按会话隔离，1 小时过期）。漏记等于白抽——素材不会被标记为已读，覆盖度统计也就没有样本。

## 它优化的是覆盖度，不是「有没有用」

这一点是本插件最容易做错的地方，所以单独说明。

**它不拿自评的 `hit` 调整权重。** 两个理由，第二个更要紧：

1. **自评不构成证据。** 用大模型判断「有没有新意/有没有用」是有实测问题的：
   换一种提示词，成对判断的准确率能摆动几十个百分点；模型还倾向于把自己产出的东西判为新；
   而专门为此训练的评估器甚至不如一句便宜的提示词。让刚读完素材、并且知道插件希望它有用的模型
   给自己打一个 `hit`，恰好就是这类判断。
2. **「有没有用」根本不是长期研究该优化的目标。** 素材的价值经常**延迟兑现**：
   今天看着完全用不上的结构，可能是三个月后工作的枢纽。而 `hit` 是**今天**盖的章。
   于是这个回路不只是加噪声——它会把延迟兑现的素材标记为失败，并且学会避开**恰恰值得留着的那批**。
   按项目累积下去，偏差正好长在最需要宽度的地方。

**它改用的两个信号**，都是可观察、廉价、且不会退化成胆小的：

- **`landed`（即时痕迹）**：要求写明结构**去了哪里**（`landed: "docs/设计.md §3"`）。
  写不出地点就不计入。这问的是**产物**而不是对素材的感觉，而且**人可以核对**。
  仍然可能出错（写了个看起来合理、其实无关的路径），但它**可查**，自评不可查。
- **覆盖度（结构广度）**：本项目**已经读过**多少结构核心、多少个来源领域。
  它只是读取历史的属性，热情吹不动它，而且它把人推向**更多样**而不是更少。

权重因此刻意做得温和且有界：

- **权重有界**（×0.85 ~ ×1.25），永远不是过滤器。插件存在的意义就是拿到**远**素材，
  所以「读透了」的类别仍然会出现，只是频率略降。不给你意外的抽卡机毫无价值。
- **样本够才生效**（本项目至少 15 条读取记录）。否则前几轮笔记就会把抽样锁死在当时碰巧抽到的东西上。
- **中立点是「读取率」而不是「占比」**：某个类别/结构核心的读取次数，与「按本项目目前的整体速度
  读完所有素材时它该被读几次」相比。读得相对多就降频，没读过的顶格加权，
  有落点的给一次**有界的**抬升。全读均匀的项目里，各桶基本不动。

覆盖度按**项目**统计（不是全局），因为一条素材在写代码时有用、在写诗时未必。
`serendipity_stats` 会分别列出各类别/各结构的「已读 N 次、落点 M 次、权重 ×W」，
以及整体的「有落点条数」与「自评有用条数」——**两个数字永远不合并成一个**。
记录太少时会明确说「样本不足，不做调整」。

## 「当时没用」的想法，后来有用了怎么办

这是本插件最想解决的场景，所以有一条**专门为它设计的通道**。

难点在于：`landed` 是**写笔记的那一刻**记录的。一条素材当时没找到位置，就会被记成「落点为空」。
如果此后没有任何机制让它重新出现，那么**延迟兑现就永远不会被记录下来**，
而被计入的那个信号就永久偏向「立刻就能用上」的东西——恰好是设计要避开的偏差。

所以有三件事：

1. **补记是一等公民，不是改错。** 同一个 id 可以**以后**再调一次 `serendipity_note`，
   把当时写不出的 `landed` 补上。插件会把它**补进原来的记录**（不新建条目）、记下落点发生的时刻，
   并算出它从「被读到」到「用上」隔了多久。`serendipity_note` 的说明里明确鼓励这么做
   （"COME BACK LATER"）——延迟兑现的前提本来就是：第一次写笔记时不可能知道。

2. **每次 draw 会把一两条「当时没找到落点」的旧素材递回来**（`reconsider` 字段）。
   按**读过多久**排序，最老的优先——放得越久，越可能被后来的进展追上。
   每条都写明「N 天前读过」，并直接给出该做的动作。
   - 只有**写过笔记、且写明落点为空**的条目才算候选。只是抽过、没读过的不是候选——那是还没读。
   - 有 **24 小时冷却**：几分钟前刚记完「用不上」的东西不该马上被反问一遍，
     那会变成对自评施压，而这个插件正想摆脱自评。

3. **延迟本身被测量、并被报出来。** `serendipity_stats` 会给出
   「有落点的条目中，N 条能算出读了多久才用上：中位 X 天、最长 Y 天」。
   这是对「价值会延迟兑现」这个假设**唯一可观察的证据**，所以宁可量它，也不假设它。
   ——但它**不是优化目标**：去追这个数字就会重犯「按自评学习」的错，它只用于观察。

## 素材库

115 条内置素材，六类（对应三种素材需求）：

| category | 中文 | 条数 | 适合 |
| --- | --- | --- | --- |
| `pattern` | 他域规律 | 22 | 需要为某个具体情况总结规律时（临界慢化、迟滞、自组织临界、拓扑保护、相变普适类…） |
| `device` | 他域做法 | 23 | 需要解决一个具体问题时找可借鉴的方法（对照随机化、析因设计、消融实验、失效树、双重差分…） |
| `surprise` | 反直觉发现 | 20 | 需要打破常识约束时（随机共振、拥堵提高通过量、毒物兴奋效应、杰文斯悖论…） |
| `everyday` | 生活观察 | 25 | 生活小技巧类迁移（先冻再切、种子催芽、和面要醒、热锅冷油、铁锅要养…） |
| `formal` | 形式系统 | 14 | 迁移距离最远的抽象结构（不动点、对偶、分形维数、最大熵、反问题不适定性…） |
| `aesthetic` | 艺术结构 | 11 | 游戏/艺术创作找「有趣」的结构（变奏、留白、不谐和音延迟解决、蒙太奇、俳句切字…） |

每条素材的字段：`label / origin / structure / summary / detail / bridge / structureTags / tags`。
`detail` 必须写清**机理**（否则只能做表面类比），`bridge` 必须是逼人做关系对齐的问句。

**`origin` 是「远」的唯一信号**，所以它必须是真正的来源领域、且尽量不重复。
实测：把「日常厨房」这类泛称收敛成真正的领域（食品科学 / 高分子物理 / 传热学 / 化工 / 表面科学 /
材料表面工程）之后，115 条素材的独立来源领域从 107 个升到 **114 个**——每条素材几乎都带来一个不同的知识域。
`npm run lint:corpus` 会监控这个比值（低于 0.85 就告警），防止它悄悄退化回几个泛称桶。

### 结构标签是两层词表

`structureTags` 是跨域检索与去重的骨架，所以不能任其碎化——不加约束时，115 条素材会散出
245 个互不相同的标签，绝大多数只出现一次，检索、`bias` 和多样性控制都会失效。现在分两层：

- **受控核心**（`lib/structure-tags.mjs` 的 `CONTROLLED`，76 个）：跨领域可迁移的「结构形状」，
  是检索、`bias`、多样性控制的单位。
- **细节标签**：素材里仍可写得更细，但必须能在同一文件的 `TAG_ALIASES`（285 条）里映射到某个核心；
  映射不上 lint 会报错。当前覆盖语料里全部 245 个标签。

新增素材时先想清楚「它属于哪种结构」，再决定要不要扩词表。

### 领域地名志：223 个「可以去看的地方」

语料之外还有一份**领域清单**（`lib/fields.mjs`），用于 `scope: "generate"`。它按 13 个家族组织
（工程与制造 / 医学与生理 / 生态与地球 / 生物与分子 / 数学与形式 / 经济与管理 / 法律与制度 /
艺术与工艺 / 语言与符号 / 军事与应急 / 体育与身体 / 日常与民间 / 计算与系统），每个家族一句
「这里的看点是」。收录标准写在文件头部，其中最重要的一条是**必须具体**：「化学」不是一个领域，
「电镀与表面处理」「界面化学」才是——领域越具体，里面的做法越具体，搬到别处时越不容易退化成空话。

这份清单和语料是两种东西：语料是**素材**（已经提炼好、可以直接读），地名志是**方向**
（还要去那里找一件真事、写出机理）。前者有边界，后者可以一直加。

## 数据存放位置

```
~/.dsh/dsh-serendipity/
├── projects/<projectKey>.json     # 每个项目抽过哪些素材、命中与否（项目间隔离）
├── stats.json                     # 跨项目累计计数（含外部素材落点、单独计数）
├── MATERIAL-MODEL.md              # agent 对素材库的持续评估（人工可读）
└── corpus/<category>.json         # 你自己/agent 沉淀的素材
```

每个项目的记录（`projects/p-*.json`）里除了每条素材的抽取与笔记，还记着三样小东西：
`tools`（各工具调用次数，用于「这个能力有没有被用过」以及只提示一次的建议）、
`generated`（最近 24 组「领域 × 结构核心」配对，避免随机生成反复落在同一个方向），
以及 `sessions`（每次会话的抽取指标：首次抽取在第几轮第几步、抽了几次几条、多少条写明落点；
最多保留 20 次，见「会话报告」一节）。

读取一律容错：文件损坏按空状态继续并记一条告警，绝不让使用历史丢失导致会话失败。

## HTTP 只读接口

`GET /api/dsh-serendipity/summary`、`/corpus?category=&q=&limit=`、`/vocabulary`、`/model`、
`/sessions?cwd=&limit=`、`/settings`（仅 loopback + 同源；只读，不提供写入接口）。

`/sessions` 回答「那次会话到底抽了没有、多早抽的」：每次会话的 `firstDraw`（轮/步/该轮开场后多久）、
`draws`／`itemsServed`／`notes`／`noted`／`landed`。因为 HTTP 侧没有会话，它默认报宿主进程的工作目录，
可以用 `?cwd=<项目目录>` 指定要看哪个项目；`enabled: false` 表示会话报告已被设置关掉
（**空列表与关闭是两件事**，不能都读成「没抽过」）。

`/settings` 是**配置诊断**：报告配置接线的状态（`declared` / `schema-unavailable`）、
配置写在哪个 profile 条目（`entryId`）、设置服务在不在（`service`）以及插件当前真正生效的配置。
排查「我改了配置怎么没生效」时先看它。

## 配置

### 配置存在哪（dsh 0.2.0 起）

**`~/.dsh/settings.yaml` 已经不存在了。** 0.2.0 启动时会把旧文档改名为 `settings.yaml.imported`
并把里面的段落逐段迁移到 profile 条目；从那时起，插件的可编辑配置就是
**profile 的 `cordis.patch.yml` 里本插件条目的 `config:` 块**：

```yaml
# ~/.dsh/profiles/web/cordis.patch.yml
- id: serendipity
  name: "@1603801678/dsh-serendipity"
  config:
    drawMode: "onRequest"   # off | onRequest | autonomous（默认）
    enabled: true           # 总开关（等价于 drawMode: off）
    announceToAgent: true   # 是否在系统提示词里声明本插件
    serveRoutes: true       # 是否挂载只读 HTTP 接口
    sessionReport: true     # 是否记录每次会话的抽取指标（关掉则完全不记录）
```

机制上，插件 `lib/index.js` 导出 `Config`（schemastery schema，字段都标了 `.volatile()`）：
**只有 volatile 字段**会出现在设置页里、也只有它们能被设置服务写。volatile 字段解析后是
**活引用**（`{ get() }`），宿主提交改动时就地改写引用并广播 `loader/volatile-update`，
插件据此重新挂载工具与提示词段落——**不重启、不重新 apply**。

### GUI 开关：「设置 → 素材抽取（缪斯）」

插件自带浏览器半边（`lib/client.js`），所以设置页里会多出一个 **「素材抽取（缪斯）」** 页面：

- **抽取模式**：自主（默认）／按需／关闭 —— 单选，每个选项都写明它意味着什么
- **总开关**：关掉等价于把模式设为「关闭」
- **在系统提示词里声明本插件**：只在「自主」模式下有意义（其它模式下控件禁用）
- **会话报告**：记录每次会话的抽取指标（第几步首次抽、抽了几条、多少条写明落点）。
  关掉后**完全不记录**——不只是不显示
- 保存／撤销改动，并提示**改完立即生效**

**改完不需要重启 dsh web**：卡片 `POST` 插件自己的 `/settings` 路由，路由经设置服务
`settings.update('serendipity', patch)` 写入 profile 条目；引用就地更新，工具与提示词段落随即重新注册。

> 它注册进官方 `settings.section` 插槽（与第三方插件的「人格设定」「关于」同级），而**没有**走官方的
> `settings.plugin.item` 卡片机制——那套需要 SDK 自带的 UI 组件与分阶段表单机制，
> 在没有浏览器可调试的情况下手写，很容易做成一个什么都不渲染的卡片。
> 这里只用 React + `fetch`，配置读写交给插件自己的路由。

### 用命令改配置（等价路径）

```powershell
node tools/set-config.mjs --show                    # 看当前设置
node tools/set-config.mjs drawMode=onRequest        # 写入 profile 里 serendipity 条目的 config
node tools/set-config.mjs enabled=false             # 关掉
node tools/set-config.mjs --profile web drawMode=off
```

工具只改**本插件条目自己的 `config:` 块**：其它条目、注释、`!!js` 表达式都按字节保留；
写入前会回读校验（新值能读回、别的条目没丢），并备份一份 `.bak-before-set-config`。
默认 profile 取 `--profile`，其次是 `DSH_PROFILE` 环境变量，最后是 `web`。

### 容错

写入口（GUI 卡片与路由）会**先校验再写**：未知配置项、非布尔的开关、非法 `drawMode` 一律被拒并报错。
手改 profile YAML 写错了则**降级为默认档**——手写配置的一个笔误不该让插件加载失败。

### `drawMode`：三档控制「插件是否主动参与」

| 取值 | 工具是否注册 | 是否在提示词里声明 | 效果 |
| --- | --- | --- | --- |
| `autonomous`（默认） | ✅ | ✅ | agent 自己判断什么时候该抽素材——推荐，也是设计初衷 |
| `onRequest` | ✅ | ❌ | 工具存在但模型不会主动提；**你先要求，它才用** |
| `off` | ❌ | ❌ | 完全不挂载 |

`onRequest` 是「可用但不主动」这一档：适合你希望保留这个能力、但不希望模型在每次设计任务里
都自己去抽素材的情况。旧的 `announceToAgent: false` 配置会自动映射到这一档，行为与以前一致；
配置写错时降级为默认档，不会让插件加载失败。

### 会话报告：这次会话到底抽了没有

**来历（真实事故）**：一次开放式提问（「请帮我看看本项目有没有可以改进的地方」）之后，
用户以为插件**一次都没抽**——实际上模型在第 23/60 步抽了 6 条、其中 3 条写进了交付文档
（`_work/项目改进审阅_20261012.md` 的 §B5/§B2/§E-2），但 86 次工具调用里只有 3 次是缪斯、
整轮又不向用户交手，不翻到那一步就看不见。**「有没有用」必须能从记录里读出来，而不是靠回忆。**

三个地方能读到同一件事：

| 位置 | 看什么 |
| --- | --- |
| `serendipity_stats` 的【本会话】段 | 首次抽取在第几轮第几步、抽了几次几条、记录几条几处落点，另有最近几次会话 |
| `GET /api/dsh-serendipity/sessions?cwd=<项目>` | 同上，机器可读（含 `firstDraw.elapsedMs`、`reminders` 等） |
| `node tools/session-report.mjs <session.jsonl>` | 从导出的会话转录直接算，不需要插件侧记录 |

这些数字**只描述、不打分**：没有任何一项参与抽样权重（理由同「不用自评学习」——素材的价值常常延迟兑现）。
`sessionReport: false` 会**连记录一起关掉**，而不只是隐藏显示。
