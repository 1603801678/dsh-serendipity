# dsh-serendipity 设计计划

> 本文件是插件设计的核心文档，记录「为什么这么设计」。实现进度与待办见 `TODO.md`。

## 一句话

给 AI 一个**缪斯式的随机素材源**：agent 按当前工作的创造性需求，主动索要跨领域素材，
阅读后被迫与自己的问题建立**远距离结构类比**，并记录哪些类比真的带来了突破——
素材库因此越用越丰富，形成正反馈。

## 从《项目目标.md》推导出的设计约束

| 项目目标的判断 | 对应设计 |
| --- | --- |
| 创新的核心是跨领域知识的结构性迁移（波尔←太阳系，李斯特←农业消毒） | 素材必须带**结构标签**与**桥接提示**，而不是给一堆事实；抽取时要**最大化源领域差异** |
| 第一层：远距离类比是「关系映射」，不是表面相似 | 素材以「机制/做法/形式」为单位（可迁移的结构），而非「话题」；给的是结构而非答案 |
| 第二层：约束的有意违反 | `serendipity_draw` 支持 `violate`/`bias` 参数：明确要求「反过来想」「哪一个常识约束是假设而非必然」 |
| 第三层：组合式 → 转化式创造 | `serendipity_note` 的 `transformation` 字段专门记录「这次是否改变了问题的定义/概念空间本身」，并统计分析 AI 的转化式产出比例 |
| AI 局限一：远距离类比的「关系对齐」不稳定 | 每条素材的 `bridge` 直接给出「这条结构可以怎么映射到你的问题上」的提问式提示，把对齐这一步做实 |
| AI 局限二：缺转化式创造机制 | 把「转化式」当成可记录、可统计、可被提示词引导的一等公民 |
| AI 局限三：缺「意外性」机制 | 素材随机 + 去重 + 跨域交错；允许「这条素材用不上」——不要求产出，但要求**记录一次失败的连接尝试**，因为意外来自大量失败的连接 |
| 素材是随机素材，不是每次都派上用场 | 抽取成本极低、无需理由即可抽取；`serendipity_note` 允许 hit=false |

## 三层结构

```
素材库（共享、只增不删）        使用记录（按项目隔离）           模型沉淀
data/corpus/*.json      ──▶  ~/.dsh/dsh-serendipity/      ──▶  ~/.dsh/dsh-serendipity/
category / tags /              records/<projectId>.jsonl        MATERIAL-MODEL.md
structure / bridge             used / hit / transformation      agent 对素材库的批判
```

- **素材库**：随插件发布，人工/AI 共同维护，质量优先。`id` = hash(origin|label)，稳定不变。
- **使用记录**：按项目隔离，`draw` 时默认排除已抽过的条目（避免同一项目重复拿同一条素材）。
- **模型沉淀**：`serendipity_note` 可以把工作中学到的新素材写回库（`serendipity_learn`），
  让插件在使用中自我扩张。

## 素材条目的 schema

```jsonc
{
  "label": "标题",
  "origin": "来源领域",              // 物理学 / 生物学 / 日常生活 / 音乐 ...
  "structure": "结构类型",           // 反馈 / 自催化 / 阈值 / 冗余 / 对称破缺 ...
  "summary": "一句话讲清是什么",     // 20~40 字
  "detail": "机理细节",              // 60~200 字，必须讲清「为什么有效/为什么反直觉」
  "bridge": "桥接提示",              // 提问式：这条结构可以怎么映射到当前问题
  "structureTags": ["反馈", "延迟"],
  "tags": ["控制系统", "震荡"]
}
```

设计要点：
- `detail` 必须包含**机制**（为什么会这样），否则 agent 只能做表面类比 —— 直接对应局限一。
- `bridge` 是**问句/祈使句**，逼 agent 做关系对齐，而不是读完就过。
- `structureTags` 是跨域检索与去重的骨架，全库共享一张受控词表。

## 六个类别（对应项目目标里的三种素材需求）

| category | 中文 | 对应需求 | 例子 |
| --- | --- | --- | --- |
| `pattern` | 他域的规律 | 「总结特定情况下的规律」 | 林线效应、临界慢化、生态位构建 |
| `device` | 他域的做法 | 「解决一个科学问题」 | 医学的对照、工程的冗余、农业的轮作 |
| `surprise` | 反直觉发现 | 「需要打破常识约束」 | 添加噪声反而增强信号、干旱促花 |
| `everyday` | 生活观察 | 「人们生活中的小技巧」 | 腌肉先冻、催芽、拔河节奏 |
| `formal` | 形式系统 | 最抽象、迁移距离最远 | 不动点、对偶、哥德尔、分形维数 |
| `aesthetic` | 艺术结构 | 游戏/艺术创作的「有趣」 | 变奏、留白、不谐和音的延迟解决 |

各分类的实时条数以 `serendipity_stats` 或 `npm run lint:corpus` 的输出为准，不在此处写死（会漂）。

## 第一轮迭代的修正：结构标签必须归一

初版让每条素材自由写 `structureTags`，结果 115 条素材散出了 **245 个互不相同的标签**，
绝大多数只出现一次。这直接击穿了整个设计——抽取时的「结构尽量不同」、`bias` 的结构倾向、
跨域检索，全都建立在这个标签空间上；标签一碎，这些机制就退化成随机。

修正是两层词表（`lib/structure-tags.mjs`）：**76 个受控核心**是检索与统计的单位，
素材仍可写更细的标签，但必须经 285 条别名映射到某个核心，否则 `npm run lint:corpus` 报 FAIL。

教训是通用的：**任何用来做检索/去重的自由文本字段，最后都会碎掉；必须给它一个受控词表。**

## 工具 API

- `serendipity_draw({ count, purpose, bias, violate, avoid, allowRepeat })`
  → 返回 N 条素材（跨域交错、结构多样的贪心选择），每条带 id / 结构 / 桥接提示 / 阅读要求。
- `serendipity_note({ items: [{ id, hit, note, transformation }] })`
  → 记录使用结果；hit=false 同样有价值；transformation 标记是否属于「改变概念空间」的突破。
- `serendipity_learn({ label, origin, structure, summary, detail, bridge, tags })`
  → 把工作中学到的新素材沉淀进库（写入用户库目录，不污染插件包）。
- `serendipity_stats()` → 库规模、已用条数、命中率、转化式比率、模型摘要。

## 非目标（当前阶段）

- 不做 Web GUI 面板（先验证核心价值；界面后续再加）。
- 不做联网抓取（本机 wikipedia 直连超时，网络素材不可靠）。
- 不追求素材数量，追求素材质量与结构标签的准确性。
