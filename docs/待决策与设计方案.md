## 1. 用户可设置「是否开启素材抽取」

**需求**：用户希望能自己决定插件是否启用抽取。

**现状**：`enabled`（总开关）与 `announceToAgent`（是否在提示词里声明）已存在，但没有
「工具可用但不由 agent 主动调用」这一档。

**建议方案**（三档，默认中间档）：
| 配置 | 行为 |
| --- | --- |
| `drawMode: "off"` | 不注册任何工具（等于现状的 `enabled:false` 对工具的语义） |
| `drawMode: "onRequest"` | 注册工具，但**不在系统提示词里声明**，只有用户明确要求时才用 |
| `drawMode: "autonomous"`（默认） | 现状：提示词声明 + agent 自主决定抽几次 |

**难度**：低（纯配置 + `apply` 里分支）。**建议：做。**

## 2. 短期任务 vs 长期任务，谁来区分？

**需求**：用户没想好该由用户设置还是 AI 自己区分。举例：短期＝读一个灵感写短篇；
长期＝不断试错解决科学问题。

**我的判断：默认交给 agent 推断，不要新增一个「无成本的选择」。**

理由：一个 `horizon: "short"|"long"` 参数对模型是零成本的，它会在没有依据时随便填一个，
于是这个参数退化成噪声（和「请选择你的置信度」一样没用）。而插件已经有**真实信号**可用：

- 本项目已发生的 draw 次数与已记录的样本数（长期任务会累积，短期任务只有个位数）；
- `timesDrawn`、`effectiveness` 的样本量是否越过证据门槛（15）；
- 用户手上是否挂着长期 `goal`（`ctx` 里有 goal 服务时可以直接读）。

**建议方案**：
1. 插件**自己**把项目分成两档（如 `session` / `campaign`），依据是已记录的样本量与 draw 轮次，
   不向模型索要；
2. 两档的差异体现在**行为**上，而不是多一个参数：
   - `session`（短期）：一次抽取给足（默认 3~5 条），不做跨轮累积性提示，不强调「沉淀」；
   - `campaign`（长期）：提示词里明确鼓励「记录后沉淀」、把 `MATERIAL-MODEL.md` 的结论一并回灌，
     并在命中率统计足够时启用有效性权重（现有机制已按此工作）。
3. 如果**用户**想强制，给他一个配置项（而不是给模型一个参数）：`horizonHint: "auto" | "session" | "campaign"`。

**难度**：中（需要定义判据 + 两套提示词措辞）。**建议：先做「自动判据 + 行为差异」，配置项留接口。**

## 3. 收集「最新」素材（社交平台 / 论坛）

**需求**：希望能从社交平台、论坛找最新的资料。

**用户 2026-10-04 决策**：**希望插件是联网的。**

**实测（`tools/check-network.mjs`，宿主进程直接 fetch）**：

| 可达 | 不可达 |
| --- | --- |
| 机核 gcores.com（200，250KB）｜少数派 sspai.com（200）｜知乎（200）｜GitHub API（200）｜arXiv API（200）｜Crossref API（200）｜npm registry（200） | wikipedia（失败）｜Hacker News（失败）｜Reddit（失败）｜DuckDuckGo（失败） |

**已实现 `serendipity_fetch({ url, focus })`**：
- 插件自己联网抓正文；支持 HTML / JSON / 纯文本，剥离 script/style/svg/注释；
  硬上限 20s 超时、400KB 响应、9000 字符输出（防止把巨型页面灌进上下文）；只允许 http/https。
- 失败时**明确列出可达/不可达站点**，避免 agent 在 wiki/Reddit/HN/DDG 上浪费调用。
- **抓取不等于入库**：返回正文时附「提炼要求」——必须压缩成一条带 `structure` / `detail`（机理）/
  `bridge` 的条目再用 `serendipity_learn` 入库；提炼不出可迁移结构就**不要入库**。
  这条边界是刻意的：否则工具会把「网络信息大多不具启发性」这个原始顾虑变成现实。
- 详细设计见 `lib/fetch.js`。

**状态：完成。** 待观察：agent 是否会在需要时真的去抓，以及哪些来源提炼出的结构质量高。

## 4. 同领域素材也有参考价值（随机抽几款现有游戏做比较分析）

**需求**：不一定跨领域；同领域素材往往也有参考价值。能否随机抽几款已有游戏做比较分析，进而造新游戏？

**用户 2026-10-04 决策**：near 语料**不做本地库**——直接搜索更简单，AI 本身已有这个能力；
关键是插件要能**类比、分析、归纳**。

**已实现（按此决策，`serendipity_draw({ scope: "near" })`）**：
不抽语料，改为返回一份**四步比较分析任务**：
1. 找 3~5 个**真实存在**的同领域作品（用 `web_search`，要具体到名称）；
2. 逐个抽出**骨架**（核心动作 / 决策来源 / 张力机制 / 主动放弃了什么）；
3. **找共同假设**——它们全都默认成立、却没人质疑的那一条 = 该领域当前的天花板；
4. 列出它们合起来**没覆盖**的设计空间。

渲染里写明「**near 负责指出该动哪里，far 负责提供动它的结构**」，并声明它返回的是
**任务清单而不是结果**。`near` 不抽素材、不写阅读记录、不占去重预算。

**为什么不做本地同领域语料**：那等于人工维护一份必然过时的清单，而 agent 的检索能力是现成的、
且永远比插件里的副本新。**插件的价值在方法（该比什么、怎么归纳），不在数据副本。**

**状态：完成。**

## 5. 把作品拆成组成部分，逐一问「哪些部分可以做哪些改变」

**需求**：能否让 AI 在创作时把作品拆成多个组成部分，再思考哪些部分可以改
（例：卡牌游戏是否一定需要「洗牌」？是否一定需要「打出」操作？）

**判断（保留）**：这是「约束的有意违反」的可操作化。`violate: true` 只提供**刺激**，
用户描述的是一个**方法**：把「整体」拆成「部件」，把每个部件的「现状」当成「假设」，再问「必须吗？」。

**已实现 `serendipity_decompose`**：每个部件强制回答 5 个问题，其中两个**无法靠描述现状交差**
（「整块去掉会退化成什么」「替代它的 2~3 种做法，至少一种形态完全不同」）；
声明为「必然」的部件必须单独举证（举不出就改判为「假设」）；
收尾强制找**跨部件共同假设**、做**配对替换**、找**删到极限后的最小可玩核心**、检查**信息通道**是否单一。
每个「假设」接 `serendipity_draw({ bias: 该部件的结构标签 })` 找替代结构。

**状态：完成。**

## 9. 2026-10-16：把「环境」当作本项目的理论框架（**只记录，暂不实行**）

**用户的观察（原话大意）**：蛋白质折叠依赖所处环境；生物性状不止依赖基因，也受环境影响；
许多伟大发现同样依赖环境——DNA 双螺旋的解析依赖碱基 A=T、C=G 的数据**和** X 光实验。
那么 AI 的工作过程是否缺一个"环境"？能否给它加一个环境，使工作更有偏好性、灵感来源更有意义、
产出更有创造性？

**提炼出的判据（本轮最重要的产出）**：

> **环境的本质 = 不由当事人署名、且当事人无法靠改写来满足的约束的总和。**
> 它干三件事：① 提供**第二条独立约束**（单条约束定不出解，两条相交才能把可能空间掐窄）；
> ② 用**不可协商的失败**淘汰可能；③ 留下**沉积物**，改变下一步的初始条件。

三个例子的机制是同一个：序列/基因型**不决定**结果，只把可能限定在一个集合里，环境把这个集合收敛成一个。
DNA 那个例子还多出一条容易被忽略的属性——Chargaff 的比例与 Franklin 的片子都是**在知道答案之前就冻结的**，
不会因为 Watson 想建三螺旋就自动改。**冻结就是署名屏障**（科学里的预注册、双盲是同一个结构）。

**对 AI 的映射**：AI 早就有环境（上下文），但它现在是**只有相关性**的环境——用户消息、系统提示、检索片段，
全是已经有人替你判定"相关"的东西，等于在一个消过毒、配好营养的培养液里做生物学。
而且模型随时能重写自己的环境（把语境里的东西重新描述一遍就算"满足"了）。
所以缺的不是信息输入，而是**不可满足性**。关键区分是：

- **偏好**（"要有创造性"）可以被换一套说法交差；
- **约束**（X 光数据）不能交差。

**与本项目的关系**：`serendipity_draw` 干的就是"往上下文里塞入模型当下控制不了的东西"——
语料在提问之前就已定稿（冻结），`bridge` 强制映射，`decompose` 审问前提，
`collide` 基本是"两条独立约束相交"的直译。**这套环境论可以当本项目缺失的那层设计依据。**

**用该框架体检现状，三处偏软**：

1. **淘汰是自评的**：`landed` 由模型自己写，记 miss 不付出任何代价。环境能杀死东西才是环境，
   现在的环境只会记录。这与 TODO 里 agent 自己提过的"落点造假只能靠自觉、链上没有卡点"是**同一条**，
   两处独立证据合流，值得优先。
2. **沉积物没有长回去**：素材入库、落点记录都在累积，但这些历史基本不参与塑造下一次抽取的初始条件。
   生态学里最要紧的一环是**生态位构建**（海狸修出池塘，池塘再选择海狸），现在这个回路只有雏形。
3. **"提炼成结构"可能是驯化**：要求外部材料必须降维成结构才入库，对可迁移性是对的，
   代价是把它的陌生性消了毒。**可携带性与抵抗性在这里此消彼长**，应当作为一个明确的取舍对待，
   而不是当成纯收益。
4. 补一条：`serendipity_fetch` 是整个插件里唯一真正接触外部世界的地方，按"因果密度"看价值最高，
   却被规则约束得最紧（不许抓首页、必须提炼）。

**候选方向（只列举，不做）**：

| 方向 | 要点 |
| --- | --- |
| 让环境能说"不" | `landed` 必须指向真实存在、且确实变了的文件/决定；对不上就是失败，而不是"记一笔 miss" |
| 建模模型的习惯 | 现在按素材覆盖度调权重（"素材抽够了没"）；更狠的是按"模型自己反复躲进哪个形状"反向避开**它的引力井** |
| 冻结机制 | 动手前钉死这次用哪条素材/哪个形状，之后不许换（预注册式）。没冻结的素材，模型总能绕过去 |
| 保留未经消化的外部物 | 允许材料以不能被翻译成本体词汇的形态存在 |
| 非语言通道 | 真实数据、真实测试、真实用户的文件。语言对语言，抵抗总是弱的 |
| 卡住时提高方差 | 细菌在胁迫下会调高突变率——卡住时应当**加大环境的权重**，而不是更用力地想（现有触发时机已踩到，只是没说原理） |
| 不可逆性 | 能无限重抽的环境不是环境。预算与不可撤销的选择才是 |

**两个边界**：

- **别做太强**：发育生物学里叫 **canalization**——表型被缓冲到环境推不动，只剩一种味道。
  要的是**有结构的可塑性**：对环境敏感但不是随机。
- **自造环境是回音室**：让模型自我批评、让 AI 生成灵感清单、让同一模型扮演"外部声音"，
  都不是环境，是自己跟自己多说几步。判据仍是那一条：**这里有没有模型没署名、又改不动的东西。**

**度量提示**：环境的效果通常体现在**方差与尾部**，不在均值。评估插件时别只看平均质量——
要看输出的分散度变了没有。（也顺便解释了为什么按 `hit` 均值学习是错的。）

**为什么不现在做**：这些改动会动到"唯一被计入的信号"的定义，而该信号目前的真实样本极少
（真实数据：11 条笔记、0 条落点）。**样本不足时改信号定义 = 加噪声。**
先按 TODO 里既有的观察项走（落点通道到底会不会被用上、`landedLag` 有没有非零值），有数据再动。

## 10. 2026-10-16：独立「素材会话」——跨项目只读的灵感会话（**只记录，暂不实行**）

**用户的想法**：单独开一个会话，AI 在这里能大致了解**同设备中其它项目**的主要内容和难点；
但这个会话**只用于寻找和阅读新素材、提供和记录灵感，不作用于其它项目本身**。

**判断：可行，而且可取——现有插件已经提供了大部分基础设施。**

**可取之处**：

1. **它就是 §9 判据的一个具体实现**。那个会话的环境由"别的项目的现场材料"构成：
   模型没署名、改不动、有真实抵抗性。这比抽象的"上下文环境"要硬。
2. **隔离解决了那个矛盾**：环境必须能施加约束，但不能造成破坏。产物只准落在素材库、改动权限为零，
   约束与安全在这里不冲突。
3. **"读而不作用"是刻意的无目的状态**，与项目已确立的哲学一致（`hit` 降级、落点延迟兑现、
   `reconsider` 通道）。如果把它塞进真实工作会话，它立刻会被"现在有用吗"压回去，
   而本项目已经证明那个压力会毁掉信号。
4. **"本机其它项目"是现成的远距离来源领域，而且带机理**——不是摘要的摘要。
   现在制造远距离靠的是语料的 `origin`（114 个独立来源领域），这是另一条真实补充通道。
5. **机制上已经就位**（这条最值得注意）：`~/.dsh/dsh-serendipity/` 的**素材库、跨项目统计、
   `MATERIAL-MODEL.md` 本来就是跨项目共享的**，只有使用记录按项目隔离；
   而 `serendipity_note` 的 P0-1 改动（接受自起 `id` 或 `label`、外部素材单独计数、
   **不进覆盖度**）**恰好就是给这类外部落点预留的接口**。
   所以缺的不是库，是**入口**（准许它读别的项目）+**隔离**（不准它写别的项目）。

**关键前提（不满足则不可行）**：

1. **只读必须是机制，不是提示词。** 本项目已有证据说明提示词护栏会被自行合理化绕过
   （模型会自问"用户没提这合适吗"；落点可指认性"只能靠自觉、链上没有卡点"）。
   可考虑的形式：该会话 cwd 是一个只用于写素材的独立目录，其它项目只经显式**只读快照**进入上下文。
2. **读什么决定它的价值：必须读项目的现场**（真实文件、TODO、失败日志、遗留问题），
   **不能读一份"项目简介/摘要"**。摘要正是 §9 批评的"预消化环境"——抵抗性被抽掉了，
   产出会退化成泛泛的灵感清单。
3. **难点才是有意义的钩子**：意义不是材料的属性，是**材料撞上某个已经存在的承诺**时的属性。
   所以那个会话应当知道各项目"卡在哪"，但**不被许可去解决它**。用户描述的边界正好就是这个。
4. **落点必须落在会话内部**：它的 `landed` 只能指向素材库（新素材条目 / 灵感记录），
   不能指向别的项目文件。这条把"不作用于其它项目"从愿望变成结构。
5. **可见性与隐私**：跨项目阅读会把 A 项目的内容带进 B 项目的上下文，
   需要一份"哪些项目可读"的显式清单。本机已有可借鉴的先例：
   ssh 插件是"主机由用户在 GUI 中配置后 agent 方可用"。
6. **别让它退化成回音室**：若它读的是模型自己写的摘要，或产出只停在对话里不落库，
   它就只是自我对话多绕了几步。仍按 §9 判据验收。

**方案草图（只记，不做）**：

- 一个专用 profile/会话（如 `material-hunter`），cwd 指向独立素材目录；
- 一份显式「项目可读清单」配置（对齐 ssh 插件"用户先配、agent 后用"的先例）；
- 只读快照通道：按项目生成快照（真实 TODO / README / git log / 失败记录），不直连别的项目的写权限；
- 产物出口：`serendipity_learn`（新素材）+ `serendipity_note`（外部来源落点，自起 id/label）；
- **它唯一的成功判据**：抽入的素材是否真的被别的项目抽取并记下落点——
  素材库是共享的，所以这件事**可以跨项目测量**，不需要它自己去汇报。

**风险**：项目现场通常包含大量与素材无关的工程细节（代码、日志），提炼成本高、产出率可能很低。
**所以建议的第一步不是写机制，而是手工试一次**：人工挑一个项目，让一个会话读一遍，
数一数能提炼出几条**真结构**。用实测产出率决定值不值得做成机制。

**难度**：中。**状态：只记录，暂不实行。**

**顺带一个观察**：这个构想会把素材库从"跨领域"扩展成"跨项目"，
并且第一次让插件拥有一个**属于它自己的、非工作性的会话形态**——
按 §9 的说法，这本身就是给 AI 加环境的一条通道。
