# 同类工作调研与改进建议（2026-10-04）

用户要求：搜索与本插件类似的工作，提出改进意见（**不要直接改代码**）。
本文件只做调研与建议，供用户决定。结论写在最前面。

---

## 0. 一句话结论

调研到的三类工作都指向同一件事：**本插件目前最强的部分是「素材的结构化」和「强制映射」，
最弱的部分是「把模型的自我报告当成真值」，以及「只做远域、不做距离控制」。**

有 **5 条**值得做的改进，按我的推荐排序：

| # | 建议 | 依据 | 影响面 | 成本 |
| --- | --- | --- | --- | --- |
| 1 | 不要把 `hit`/`transformation` 当成效果真值 | 3 篇论文都证明 LLM 自评新颖性不可靠 | 统计与学习机制的地基 | 低-中 |
| 2 | 保留**被拒的**候选及其理由 | 论文把拒绝理由当一等产物 | 抽取日志 | 低 |
| 3 | 距离控制：把 `bias` 改成显式的「远近平谱」 | Scideator 的第三个设计要点 | 抽取质量 | 中 |
| 4 | 素材加一层「关系/作用」而不仅是「结构」 | Auto-Research 的核心批评 | 语料 schema | 中 |
| 5 | 内建评估：不靠自评，靠外部可检验信号 | novelty mirage / RQ-Bench | 项目可信度 | 中-高 |

另有一条**顺手可修的体验问题**（不是改进意见，是 bug）：`serendipity_fetch` 抓 PDF 会返回乱码字节
（本次实测 973KB 的 PDF 被当纯文本返回）。

## 1. 调研到的工作

### 1.1 Scideator：facet 重组 + 距离控制的检索

[Scideator: Human-LLM Compound System for Scientific Ideation through Facet Recombination and Novelty Evaluation](https://dlnext.acm.org/doi/pdf/10.1145/3786335.3813161?download=true)
（arXiv [2409.14634](https://arxiv.org/abs/2409.14634v7)，Radensky 等，含用户研究）

三个设计要点：

1. **facet 重组**：把论文拆成 **purposes / mechanisms / evaluations** 三类 facet，让用户交互式重组。
2. **距离控制的检索**（Analogous Paper Facet Finder）：显式提供「从同一主题到完全不同领域」的**谱**，
   而不是单一地往远处推。
3. **facet 化的新颖性核验**：retrieve-then-rerank，用 facet 而不是整篇文本比对。

**用户研究结论**：相比「同一个基座 LLM 去掉这些模块」的基线，**在 idea exploration 与 expressiveness
上显著更好**。

> 对本插件的意义：它的第 2 点是本插件**唯一缺的一块**——本插件只有「远」（`ORIGIN_CAP`、
> 跨域交错、`violate`），没有「距离谱」。而且这是三个要点里**唯一有用户研究支撑**的。

### 1.2 Auto-Research：把「扁平对象」当成结构性缺陷

[Toward Auto-Research: Mining Falsifiable Research Ideas from Paper Knowledge Graphs with
Categorical Structure](https://arxiv.org/abs/2608.20361v1)（arXiv 2608.20361）

原文对现状的批评（几乎逐字命中本插件的做法）：

> 「基于 LLM 的自动研究想法生成系统有一个共同的**结构性弱点**：它们把构思简化为
> **自由文本重组（free-text recombination）**、**随机配对（random paper pairing）**
> 或 **嵌入相似度检索（embedding-similarity retrieval）**。三者的失败方式相同：
> 都把论文当成扁平对象（字符串或向量），从而**抹掉了研究者在做跨域类比时真正使用的
> 类型化的 问题—方法—指标—论断 箭头**。」

它的做法：把每篇论文建模成一个小范畴（对象＝类型化实体，态射＝论文断言的**关系**），
跨论文的桥＝保持对象种类与关系类的**部分函子**；三层算法＝范畴签名聚类 → 函子保持门 →
六轴 LLM 合理性裁判。

**结果**：范畴门以约 **17:1** 的比例过滤跨域候选，而**被接受想法的可定量证伪率保持在 83% 以上**；
并且**每个被拒候选连同它的逐轴理由都被保留**，所以这道门同时是一层日志，而不是静默过滤器。

> 对本插件的意义：本插件的每条素材恰恰就是「一个扁平对象」——
> `structure` 是一句短语，`structureTags` 是标签集合，**没有任何「关系」被表示出来**。
> 抽取时把素材映射到问题上的那一步，靠的是模型自由发挥（`bridge` 只是一句提示）。
> 这与它批评的对象是同一类结构。

### 1.3 Causal Signatures：WHAT / WHY / HOW 三对齐

[Causal Signatures for Cross-Domain Reasoning - Enabling Functional Analogy Through WHAT/WHY/HOW
Alignment](https://zenodo.org/records/18207546)（预印本，DOI 10.5281/zenodo.18207546）

把类比定义为**因果功能上的结构等价**，用三个对齐维度表达：
**WHAT**（它做什么／承担什么功能角色）、**WHY**（它为什么存在）、**HOW**（它怎么运作），
声称可以脱离领域、表征与词汇来识别深层功能类比，并因此**减少伪相似与幻觉**。

> 对本插件的意义：这几乎就是本插件 `structure` / `detail` / `bridge` 三个字段想做的事，
> 但本插件的三字段是**给读者看的散文**，不是**可对齐的槽位**——没有任何机制检查
> 「这条素材的 WHAT 与当前问题的 WHAT 是否对得上」。
>
> 另需注意：该预印本为独立研究者所著、未见同行评审，**当作思路来源可以，当作实证依据要谨慎**。

### 1.4 LLM 自评新颖性不可靠（三篇，方向一致）

这是本次调研里**最该重视**的一组结论，因为本插件的有效性学习完全建立在这个前提上。

- [Old Ideas, Novel Problems: The Instability of LLM-Based Novelty Evaluation](https://arxiv.org/abs/2610.02022v1)
  （arXiv 2610.02022）：对 6 个裁判做系统对照研究。**仅仅在提示里告诉裁判「评审认为其中一个想法是新的」，
  就能在超过一半的**同卵**想法对上改变判决，成对准确率**摆动超过 50 个百分点**，
  有时**低于随机**。同一处改动对某个裁判有帮助、对另一个有害。检索与更大的推理预算帮助很小；
  两个专用的新颖性评估器**被最便宜的提示基线打败**。作者由此质疑所有自动构思系统报告的「新颖性提升」。
- [On the Limits of LLM-as-Judge for Scientific Novelty Assessment](https://arxiv.org/abs/2606.12071v1)
  （arXiv 2606.12071，RQ-Bench）：LLM 裁判**一致地**把模型生成的研究问题评为高新颖性，
  形成 **novelty mirage（新颖性海市蜃楼）**；而**领域专家得出相反结论**，更偏好人类作者锚定的问题。
  作者还发现很多生成的问题**狭窄或附属于原文**，而 LLM 裁判通常测不出这一点。
- 上述 Scideator 的 facet 化核验，也是一种「不要靠整篇文本自评」的应对。

> 对本插件的意义：本插件的 `hit`、`transformation` 都是**由同一个 agent 在同一个上下文里自评**的，
> 而且这个 agent 正是刚刚读了素材、并且**知道插件期望它判断「有用」**的那个。按上述结论，
> 这个信号至少有三种已知偏差：①提示措辞主导判决；②系统性高估；③无法区分「真的新的」与
> 「只是我没见过的」。而 `effectiveness.js` 的权重学习是以它为真值的。

## 2. 改进建议

### 建议 1（最推荐）：把「自评」降级，给统计与学习换一个地基 —— ✅ **已实现（2026-10-04 二轮）**

**问题**：`effectiveness.js` 用 `hit` 学权重、`serendipity_stats` 报命中率，但 `hit` 是自评。

**当时列出的可选做法**（任选，不必全做）：

- **改为信号而非评价**：让 `serendipity_note` 不问「有用吗」，而问**可核对的痕迹**——
  「这条结构最终被写进了作品的哪个部分」（一个位置/一句引用）、「它改变了哪一条此前写下的设计决定」。
  有具体落点才算命中，比「我觉得有用」抗操纵得多。
- **把自评与痕迹分开存**：现在两者混在一条记录里。分开后统计可以只报「有落点」的比例，
  而自评仅作参考——这样即使自评不可靠，统计仍然可信。
- **不要用 `hit` 训练抽取权重**：若采纳上面两条，权重可以只用「有落点」这一信号；
  或者干脆把有效性权重从「命中率」改成「被后续引用的次数」。
- **给 `transformation` 加举证要求**：现在的 `transformation` 只要填 `true` 即可，
  而根据 novelty mirage，这正是最容易被高估的字段。可以要求同时给出「改变前的问题定义」
  与「改变后的」两句话——写不出就是没变。

**为什么排第一**：它是**地基**问题。如果这个信号不可信，那么本项目所有「命中率 20%」「转化式 4 条」
这类结论都不可信，包括写进 README 的那些。

#### 实现结果（用户又往前推了一步）

上面四条**全部落地**了：`landed`（写进了哪里）、`claimedHits`（自评，只记录）、
`changedFrom`/`changedTo`（转变必须给前后定义）、权重不再看 `hit`。

但用户在讨论中指出了这份建议**没说到的一层**：不只是「自评不可信」，而是
**「优化素材是否有用」这件事本身在长期研究里就是错的**——素材价值延迟兑现，
而 `hit` 是今天盖的章，于是回路会把延迟兑现的素材判成失败并学会避开它，
偏差正好长在最需要宽度的地方。所以权重最终改成了优化**覆盖度**
（读取历史本身的属性，热情吹不动它），而不是任何形式的「成功率」。
详见 `README.md`「它优化的是覆盖度，不是有没有用」。

顺带修掉的两个真实 bug：`oneOf` 分支不互斥导致 `serendipity_note` 完全不可用；
`recordDraw` 重建条目时漏带新字段，导致**素材被重新抽到时落点被静默抹掉**。

### 建议 2：保留被拒的候选与理由

**依据**：Auto-Research 明确把「每个被拒候选连同逐轴理由」当作**一层日志**保留下来。

**现状**：本插件只保留抽过的素材 id 与 miss 标记，**不保留「为什么对不上」之外的任何结构**
（`note` 是自由文本，没有被当作筛选信号使用）。

**做法**：给 miss 的 `note` 加一个轻量的结构化维度（例如「对不上的原因类型」：
结构不存在 / 结构存在但与本问题无关 / 结构对得上但我无法应用 / 素材讲得太抽象）。
积累后可以看到**抽卡机的系统性失效模式**——例如「素材太抽象」占多数，就说明该给素材加具体化的一步；
「结构不存在」占多数，就说明库的覆盖有洞。这比只看命中率信息量大得多。

**成本**：低（一个字段 + 统计里加一段）。

### 建议 3：距离控制——把「远」从唯一方向改成一条谱

**依据**：Scideator 的第 2 个设计要点，且是唯一有用户研究支撑的。

**现状**：本插件的抽取引擎只优化「远」（来源分散、跨域交错、`violate` 偏「打破假设」）。
`bias` 是自由文本，可以填类别/标签/领域，但**没有「同领域 vs 远域」的第一等表达**。

**做法**：

- 给 `draw` 一个显式的距离维度（例如 `distance: 'near' | 'mid' | 'far'`，或把 `scope: near` 推广成三级），
  并且**在同一次抽取里按谱分配**：一部分素材来自与问题同领域、一部分中等距离、一部分远域。
- 这与现有的 `scope: near`（同领域比较分析任务）不冲突，但**方向不同**：
  现在 `near` 是「去找已有作品做基准」，而这里是「抽取时把距离当作一个可调的旋钮」。
- 依据 1.2 的另一个启示：距离不该只由「来源领域是否相同」判断。
  两个都标 `formal` 的素材可能距离很远，两个不同领域的素材可能结构上完全同构。
  **距离的定义本身值得再想**（现有的 `ORIGIN_CAP` 是「来源领域」的代理，很粗）。

**成本**：中（需要定义距离、改抽取、加测试）。

### 建议 4：素材 schema 加一层「关系/作用」

**依据**：Auto-Research 的核心批评——扁平对象抹掉了关系。

**现状**：素材字段是 `label / origin / structure / summary / detail / bridge / structureTags / tags`，
都是**对这条素材自身的描述**，没有「它在原领域里与谁发生什么关系」。

**做法**（两条路，成本递增）：

- **轻**：给素材加 `engages`（它与原领域里的什么发生作用：抵消谁、放大谁、与谁竞争），
  并在 `bridge` 里要求点明「在你的问题里，谁是那个对应的角色」。
  这把 1.3 的 WHAT/WHY/HOW 对齐落成**一个必须填的指向**，而不是散文。
- **重**：给 `structureTags` 之外补一层**关系标签**（例如「抑制→放大」「前置→触发」），
  让抽取能按「结构形状 + 关系类型」匹配，而不是只按形状。

**成本**：轻版本低（加字段 + 改语料生成 + lint 校验 + 回填 115 条），重版本中。

### 建议 5：项目级评估不要只靠自评

**依据**：1.4 的三篇 + 1.1 的用户研究。

**现状**：README 里写着命中率、转化式比率；这些都是自评。要判断「插件是否真的让 AI 更有创造力」，
目前的证据强度不足以支撑。

**做法**（挑一个可行的）：

- **对外部作品做盲评**：让插件在会话里产出两份方案（有插件 / 无插件），
  由**不清楚来源的人（你）**盲评。这是最朴素也最有效的一步，成本主要是人的时间。
- **落点计数**：统计「素材的结构最终被写进最终产物的次数」，而不是「模型说有用」的次数。
  这与建议 1 的「痕迹」是同一件事，但它同时是一个**可长期追踪的评估指标**。
- **反向检验**：抽一批素材，让**另一个没有读过原素材的 agent** 来判断
  「这个作品里哪些部分像是从外部结构来的」——若能对上，说明映射是真实发生的而不是叙事的。

**为什么不做成「LLM 裁判」**：以上三篇的结论正是**不要**这么做。

## 3. 本插件目前做得对的地方（对照调研，无需改）

- **素材只收结构、不收事实**：与 1.2 对「扁平字符串」的批评方向一致——本插件至少在语料层面
  不允许写只有内容没有机理的条目（lint 会拦）。
- **强制映射而非只给灵感**：`bridge` 是可以被批评为「散文」，但**要求逐条映射并记录**这一点，
  比多数「灵感卡片」类工具做得实。
- **记录失败**：`hit=false` 被明确当作正常结果，这与 1.2「保留拒绝理由是日志」同源。
- **对素材库做体检**：受控词表 + 来源领域重复率 + 复制粘贴检测，这类工程纪律在调研到的原型系统里少见。

## 4. 顺手可修的 bug（本次实测发现）

`serendipity_fetch` 抓 PDF 会把**二进制字节当纯文本返回**：本次抓一个 973KB 的 PDF，
返回的是以 `%PDF-1.5` 开头、`FlateDecode` 压缩流乱码为主的文本，对模型毫无用处且浪费上下文。
建议：按 `content-type` 识别 `application/pdf` 等二进制类型，直接返回
「这是 PDF，本工具不能解析；请改用 HTML 版页面（arXiv 的 `/abs/` 而非 `/pdf/`）或 API 端点」。
这也正好是本次调研自己踩到的坑——我最后改用 arXiv / Crossref 的 **API** 才拿到可用内容。

## 5. 建议的顺序

1. **建议 1（自评降级）**：它是地基，且成本低。不做这一步，后面所有统计都是自我安慰。
2. **建议 4 轻版本（`engages` + bridge 指向）**：让「关系对齐」有一个必须填的槽位。
3. **建议 2（保留拒绝理由）**：低成本的诊断能力，能反过来指导语料怎么补。
4. **建议 3（距离谱）**：价值最高但需要先想清楚「距离怎么定义」。
5. **建议 5（外部评估）**：需要你参与，但它是唯一能回答「插件到底有没有用」的一步。
